# Backend update
1. Back up dishr_test. Run migration.sql in MySQL Workbench against the existing database created by dishr_seed.sql. Do NOT rerun the destructive seed script. If starting fresh, run dishr_seed.sql first, then migration.sql. Older db_test.sql uses incompatible swipe/save table names.
2. Copy .env.example to .env and set your MySQL password and a fresh random JWT secret. Rotate the original exposed credentials. Install with `python -m pip install -r requirements.txt`.
3. Run `python -m uvicorn main:app --port 8003 --reload`; open http://127.0.0.1:8003/docs.
4. After verifying ownership outside the app, run `python create_owner.py` locally as a trusted operator. Enter the existing restaurant ID, owner name, email and business name. The script creates and links the account atomically and prints a generated password once. Deliver credentials securely. There is no public owner registration endpoint. Existing owner accounts should be audited manually; removing the endpoint does not revoke them.
5. POST /owners/login; authorize with access_token. GET /owners/restaurants; PATCH /owners/restaurants/1 with e.g. {"description":"Updated description"}. Try another restaurant; expect 404.
6. POST /promotions/test-purchase/1 with owner token. This simulates a seven-day promotion only; no money is collected. Disable ENABLE_TEST_PROMOTIONS outside demos. Real payments require a verified payment-provider webhook and checkout integration, not included.
7. Register/login as a customer via /auth. GET /restaurants/recommended. Initially review count determines rank except for promotion boost. Preference weight increases after 10 currently recorded distinct swipes, reaching 70% at 30. Likes/dislikes are smoothed per exact cuisine label; havent_been is neutral. Already swiped restaurants are excluded. Results are capped at remaining allowance.
8. POST /swipes/ with {"restaurant_id":1,"swipe_type":"liked"}; GET /swipes/remaining. Submit 10 valid requests (including updates); the 11th returns 429. Deleting a swipe does not restore allowance. Daily limit uses Halifax midnight; historical swipes before migration are not counted toward the new counter.
9. Existing routes remain available; customer-only swipe/save/review actions now check customer role. General restaurant listing is unchanged; use recommended endpoint for swipe feed.

Validation: Python compilation only; live MySQL/Swagger and concurrency tests still required. No frontend modifications. The old routes/swipe.py fragment is unused. The migration assumes the current dishr_seed.sql schema.
